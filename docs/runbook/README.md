# Runbook: развёртывание лендингов

Набор инструкций для запуска клиентских лендингов на собственном сервере:
Docker + Caddy, весь исходящий трафик сервера через VPN.

Инструкции написаны так, чтобы их можно было выполнить (или передать ИИ-агенту)
без дополнительных пояснений. Всё проверено на боевом сервере.

## Что где

| Документ | Когда нужен |

| [01-server-setup.md](01-server-setup.md) | Новый сервер: подготовка, ручная установка Docker |
| [02-vpn-full-tunnel.md](02-vpn-full-tunnel.md) | Прокинуть весь исходящий трафик через VPN, не потеряв доступ |
| [03-docker-deploy.md](03-docker-deploy.md) | **Главное.** Общие правила деплоя любого лендинга |
| [04-deploy-checklist.md](04-deploy-checklist.md) | Чек-лист: пошагово запустить новый лендинг |
| [prompts.md](prompts.md) | Готовые промты для ИИ-агента |
| [templates/](templates/) | Готовые файлы: Dockerfile, compose, Caddyfile, скрипты VPN |

## Порядок работы

**Новый сервер** (один раз на сервер):
1. [01-server-setup.md](01-server-setup.md) — подготовка + Docker
2. [02-vpn-full-tunnel.md](02-vpn-full-tunnel.md) — VPN

**Новый лендинг** (каждый проект):
3. [03-docker-deploy.md](03-docker-deploy.md) + [04-deploy-checklist.md](04-deploy-checklist.md)

Один сервер спокойно держит несколько лендингов: у каждого свой каталог,
свой compose-проект и свой домен в общем Caddy.

## Архитектура

```
        интернет
            │
      80/443│ (входящий трафик отвечает через реальный IP)
            ▼
      ┌───────────┐
      │   Caddy   │  авто-HTTPS, реверс-прокси
      └─────┬─────┘
            │ внутренняя docker-сеть
     ┌──────┴──────┬─────────────┐
     ▼             ▼             ▼
 landing-a     landing-b     landing-c   (по контейнеру на проект)
     │
     │ исходящие запросы (API, Telegram, npm)
     ▼
   VPN-туннель ──► внешний IP провайдера VPN
```

Ключевой принцип: **входящий** трафик (SSH, сайт) отвечает через реальный IP
сервера, **исходящий** уходит через VPN. Как это устроено — в
[02-vpn-full-tunnel.md](02-vpn-full-tunnel.md).

## Обозначения в инструкциях

Подставляйте свои значения:

| Плейсхолдер | Пример | Что это |
|---|---|---|
| `<PROJECT>` | `acme-landing` | Имя проекта, оно же каталог `/opt/<PROJECT>` |
| `<DOMAIN>` | `acme.ru` | Домен лендинга |
| `<SERVER_IP>` | `203.0.113.10` | Реальный IP сервера |
| `<GATEWAY>` | `203.0.113.1` | Шлюз по умолчанию (`ip route show default`) |
| `<IFACE>` | `eth0` | Внешний интерфейс (`ip -brief addr`) |
