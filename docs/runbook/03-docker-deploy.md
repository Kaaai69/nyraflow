# 03. Деплой лендинга в Docker — общие правила

Функционал лендингов различается (где-то только статика, где-то формы, боты,
интеграции), поэтому здесь — не пошаговый скрипт под конкретный проект, а
**правила и каркас**, которые работают для любого лендинга.

## Правила (нарушать — значит потом ловить баги)

**1. Один проект — один каталог `/opt/<PROJECT>` и один compose-проект.**
Проекты не пересекаются, каждый обновляется и падает независимо.

**2. Приложение никогда не публикует порты наружу.**
Наружу смотрит только Caddy (80/443). Приложение доступно ему по имени сервиса
во внутренней docker-сети (`app:3000`). Так лендинг нельзя открыть в обход
HTTPS, а порты не конфликтуют между проектами.

**3. Секреты — только в `/opt/<PROJECT>/.env` на сервере (права 600).**
Никогда: в git, в образе, в аргументах сборки. Подключаются через `env_file` в
compose. В репозитории — только `.env.example` с именами переменных.

**4. `.dockerignore` обязателен и включает секреты.**
Минимум: `node_modules`, `.next`, `.git`, `.env*`, `*.txt` с ключами, тесты.
Иначе секреты и мусор уедут в образ.

**5. Многоступенчатая сборка, в рантайме — минимум.**
Отдельные стадии `deps` → `builder` → `runner`. В финальный образ попадает
только собранное приложение, без исходников и dev-зависимостей.

**6. Рантайм работает под non-root пользователем.**
И поэтому: **`chmod -R a+rX` на статику** в Dockerfile. Иначе файл с правами
`600` (частый случай для фото, приехавших из мессенджера) окажется нечитаемым
и отдаст 500 вместо картинки.

**7. `restart: unless-stopped` у всех сервисов.**
Контейнеры сами поднимутся после перезагрузки сервера.

**8. Домены и HTTPS — только через Caddy.**
Сертификаты Let's Encrypt он выпускает и продлевает сам. Ручной работы с
сертификатами нет.

**9. Тома для данных Caddy обязательны.**
`caddy_data` хранит сертификаты. Без тома при каждом пересоздании контейнера
будут перевыпускаться сертификаты → быстро упрётесь в лимиты Let's Encrypt.

**10. После каждого деплоя — проверка HTTP-кодом, а не «на глаз».**
См. [04-deploy-checklist.md](04-deploy-checklist.md).

## Каркас проекта

В репозитории лендинга (шаблоны — в [templates/](templates/)):

```
Dockerfile            # многоступенчатая сборка
.dockerignore         # обязательно включает .env* и секреты
docker-compose.yml    # app + caddy
Caddyfile             # домены и реверс-прокси
.env.example          # имена переменных без значений
```

На сервере:

```
/opt/<PROJECT>/
├── (файлы проекта)
└── .env              # реальные секреты, права 600, не в git
```

## Первый запуск

```bash
# 1. каталог
ssh root@<SERVER_IP> 'mkdir -p /opt/<PROJECT>'

# 2. код на сервер (без мусора и секретов)
rsync -az --delete \
  --exclude node_modules --exclude .next --exclude .git \
  --exclude '.env*' --exclude '*.log' \
  ./ root@<SERVER_IP>:/opt/<PROJECT>/

# 3. секреты (один раз, руками)
ssh root@<SERVER_IP> 'umask 077; cat > /opt/<PROJECT>/.env' <<'ENV'
SOME_TOKEN=...
ENV

# 4. сборка и запуск
ssh root@<SERVER_IP> 'cd /opt/<PROJECT> && docker compose up -d --build'
```

Caddy сам выпустит сертификат при первом обращении к домену — при условии, что
A-запись домена уже указывает на `<SERVER_IP>` и порты 80/443 открыты.

## Обновление

```bash
rsync -az --delete \
  --exclude node_modules --exclude .next --exclude .git --exclude '.env*' \
  ./ root@<SERVER_IP>:/opt/<PROJECT>/
ssh root@<SERVER_IP> 'cd /opt/<PROJECT> && docker compose up -d --build app'
```

Пересобирается только `app`; Caddy трогать не нужно. Простой — секунды
(контейнер пересоздаётся после успешной сборки).

Если менялся только `Caddyfile`:

```bash
ssh root@<SERVER_IP> 'cd /opt/<PROJECT> && docker compose restart caddy'
```

## Откат

Docker хранит предыдущий образ. Если новая версия сломана:

```bash
docker images | grep <PROJECT>          # найти предыдущий image id
docker tag <OLD_IMAGE_ID> <PROJECT>-app:latest
docker compose up -d --no-build app
```

Надёжнее — деплоить с тегами версий (`<PROJECT>-app:2026-08-02`) и в
`docker-compose.yml` указывать конкретный тег.

## Варианты лендингов

Каркас один, отличается наполнение:

**Статика / SSG (Next.js export, Astro, Vite).**
Можно вообще без app-контейнера: собранный `dist/` монтируется в Caddy как
`root * /srv` + `file_server`. Меньше движущихся частей.

**Next.js SSR.**
В `next.config.ts` обязательно `output: "standalone"` — иначе образ будет
огромным и не запустится штатной командой. Рантайм: `node server.js`.

**Лендинг с формами / API-роутами.**
Появляются секреты → `.env` + `env_file` (правило 3). Помните: исходящие
запросы уходят **через VPN** — это как раз то, что позволяет достучаться до
Telegram API и подобных сервисов из РФ.

**Несколько лендингов на одном сервере.**
Два варианта:
- *Простой:* у каждого проекта свой Caddy — но тогда 80/443 займёт только
  первый. Не годится.
- *Правильный:* **один общий Caddy** на сервере, у него внешняя docker-сеть
  `web`, и все проекты подключаются к ней. В Caddyfile — блок на каждый домен.

  ```bash
  docker network create web   # один раз на сервер
  ```

  В `docker-compose.yml` каждого проекта:

  ```yaml
  networks:
    web:
      external: true
  ```

  и сервис `app` без публикации портов, только `networks: [web]`.

## Диагностика

```bash
cd /opt/<PROJECT>
docker compose ps                  # статусы контейнеров
docker compose logs -f app         # логи приложения
docker compose logs caddy | tail   # логи Caddy: TLS, ACME, ошибки прокси
docker compose exec app sh         # зайти внутрь контейнера
docker stats --no-stream           # потребление ресурсов
```

Частые ситуации:

| Симптом | Причина |
|---|---|
| 502 от Caddy | app не поднялся или не слушает `0.0.0.0:3000` |
| 500 на картинках | права на файлы (правило 6) |
| Сертификат не выпускается | DNS не указывает на сервер / 80 порт закрыт / порт не в исключениях VPN |
| Сайт не открывается снаружи, SSH жив | 80/443 не попали в исключения VPN — см. [02](02-vpn-full-tunnel.md#6-порты-80443-обязательно-в-списке-исключений) |
| Сборка виснет на установке пакетов | MSS clamping не настроен — см. [02](02-vpn-full-tunnel.md#5-зависают-загрузки-npm-install-docker-pull-большие-ответы-api) |
