# Nyraflow — Fullscreen Looping Hero Animation for React

## Задача

Переделай текущую hero-секцию существующего сайта **Nyraflow** в полноэкранную типографическую анимацию, максимально близкую по композиции, ритму и характеру движения к приложенному видео-референсу:

`Запись экрана — 2026-08-05 в 11.28.58.mov`

Видео используется **только как визуальный и motion-референс**.  
Не вставляй запись экрана на сайт и не используй её как фоновое видео.

Нужно воспроизвести эффект средствами React, CSS и существующей анимационной библиотеки проекта, чтобы:

- текст оставался идеально чётким;
- анимация корректно масштабировалась;
- последовательность проигрывалась плавно;
- цикл повторялся бесконечно, а не запускался только один раз;
- hero занимал весь первый экран;
- остальная страница продолжала работать без изменений.

---

## Контекст проекта

- Сайт уже реализован на React.
- Работай внутри существующего проекта.
- Не создавай новый проект.
- Сначала изучи текущую структуру приложения, hero-компонент, стили, маршруты, используемые библиотеки и текущий header.
- Сохрани существующую архитектуру, адаптивность и рабочие ссылки.
- Не переделывай остальные секции сайта.
- Не меняй блок цен и отдельную секцию «Мы создаём», которая будет добавлена перед ценами по другому заданию.
- Сайт студии: `https://nyraflow.ru`

# Основная концепция

Hero должен быть самостоятельной полноэкранной типографической заставкой на чёрном фоне.

Визуальный характер:

- чистый чёрный фон;
- минималистичная белая типографика;
- много свободного пространства;
- текст появляется небольшими смысловыми частями;
- отдельные слова и фразы сменяют друг друга;
- периодически появляются контрастные белые вертикальные панели, как в референсе;
- движения спокойные, уверенные и точные;
- никаких случайных частиц, градиентных шаров, 3D-объектов, видеостоков, глитча или дешёвого неона;
- впечатление премиальной digital-студии, а не шаблонного AI-лендинга.

Это **не scroll animation**.  
Анимация запускается автоматически и продолжает циклически проигрываться, пока hero находится на экране.

# Размер и расположение hero

Hero должен занимать весь первый экран:

```css
min-height: 100vh;
min-height: 100svh;
```

Учитывай мобильные браузеры и динамическую высоту viewport.

Требования:

- ширина: 100%;
- фон: `#000000`;
- отсутствие горизонтального скролла;
- контент визуально центрирован;
- учитывать высоту существующего header;
- не перекрывать меню и интерактивные элементы;
- после hero пользователь должен нормально перейти к следующей секции обычным скроллом.

Hero не должен быть фиксированным поверх всей страницы после прокрутки.

# Header и навигация

- Сохрани существующий header сайта.
- Header должен находиться поверх hero.
- Проверь читаемость логотипа, ссылок и CTA на чёрном фоне.
- Не создавай вторую навигацию.
- Не дублируй логотип без необходимости.
- Если существующий header светлый и не подходит к чёрному hero, адаптируй только его визуальное состояние над hero, не ломая поведение на остальных секциях.
- После выхода из hero можно вернуть существующую тему header, если в проекте уже реализована смена состояния.

# Анимационная механика

## Предпочтительный вариант

Если в проекте уже установлен **Framer Motion**, используй:

- `AnimatePresence`;
- `motion.div`;
- variants;
- контролируемый индекс текущей сцены;
- корректную очистку таймеров.

Если Framer Motion не установлен, сначала оцени, оправдано ли его добавление.  
Для такой последовательности разрешено использовать чистые CSS keyframes или существующую библиотеку проекта.

Не добавляй GSAP только ради простой смены сцен, если он не используется в проекте.

---

## Важное требование: бесконечный цикл

Анимация не должна завершаться после первого проигрывания.

Обеспечь:

```text
scene 1 → scene 2 → ... → final scene → fade-out → scene 1
```

Цикл повторяется бесконечно.

Не допускай:

- остановки на финальном экране;
- повторного запуска только после перезагрузки;
- накопления таймеров;
- ускорения анимации после нескольких циклов;
- двойного запуска в React StrictMode;
- утечек памяти;
- резкого мигания при возврате к первой сцене.

Все `setTimeout`, `setInterval`, animation controls и listeners должны корректно очищаться.

---

# Поведение при прокрутке и смене вкладки

Используй `IntersectionObserver`:

- когда hero видим, анимация работает;
- когда пользователь полностью прокрутил hero, цикл можно поставить на паузу для экономии ресурсов;
- при возвращении к hero анимация должна продолжиться или аккуратно перезапуститься;
- пользователь не должен увидеть сломанное промежуточное состояние.

Также учти `document.visibilityState`:

- при переходе на другую вкладку не накапливать пропущенные таймеры;
- при возвращении восстановить корректный цикл.

# Переходы

Основные допустимые свойства:

- `opacity`;
- `transform: translateY(...)`;
- `transform: scale(...)`;
- очень слабый `filter: blur(...)`;
- clip-path или mask для появления светлых панелей, если реализация остаётся производительной.

Не использовать:

- typewriter;
- glitch;
- scrambling letters;
- резкое вращение;
- bounce;
- elastic easing;
- чрезмерный motion blur;
- flashing;
- постоянный шум;
- тяжёлый canvas;
- видео;
- sequence из растровых кадров.

Предпочтительные easing-кривые:

```css
cubic-bezier(0.22, 1, 0.36, 1)
```

или аналогичная спокойная premium easing.

# Типографика

Сначала используй уже подключённый на сайте фирменный шрифт.

Не подключай случайный новый шрифт, если текущая типографика подходит.

Ориентиры:

- основной текст desktop: приблизительно `clamp(28px, 3.4vw, 64px)`;
- названия направлений: приблизительно `clamp(30px, 4vw, 72px)`;
- финальный wordmark может быть крупнее;
- мобильная версия должна сохранять иерархию, но не переносить текст хаотично;
- межстрочное расстояние плотное и аккуратное;
- вторичная строка заметно меньше основной.

Текст не должен быть микроскопическим, как в вертикальном Pinterest-превью.  
На реальном сайте композиция должна уверенно занимать экран.

# Фирменный стиль

Базовая палитра:

```text
Background: #000000
Primary text: #FFFFFF
Secondary text: rgba(255, 255, 255, 0.48–0.68)
Light panel: #F5F5F2 или близкий тёплый off-white
Dark text on panel: #101114
Brand accent: #4361FF
```

Фирменный синий `#4361FF` использовать только точечно:

- небольшой элемент логотипа;
- hover кнопки;
- тонкий индикатор;
- очень слабый акцент в финальной сцене.

Не окрашивать каждую сцену в синий и не добавлять сильное неоновое свечение.

# CTA

В финальной сцене должна быть рабочая кнопка:

```text
Start a project
```

Ссылка:

```text
#contact
```

Требования:

- кнопка кликабельна;
- не исчезает слишком быстро;
- финальный экран держится достаточно долго, чтобы пользователь успел нажать;
- кнопка не должна перезапускать анимацию;
- hover и focus состояния заметны;
- доступна с клавиатуры.

Можно также сделать так, чтобы на финальной сцене пользователь мог задержать курсор над CTA, а цикл ненадолго поставился на паузу. Это допустимо только при простой и надёжной реализации.

---

# Mobile

На мобильных hero также должен занимать весь первый экран.

Не отключай концепцию полностью.

Адаптация:

- сократи расстояния;
- уменьши масштаб белых панелей;
- допускается перенос вводной фразы максимум на две строки;
- названия направлений должны помещаться без обрезания;
- `Telegram Apps` не должно ломать сетку;
- сохранить спокойный темп;
- проверить Safari iOS;
- использовать `100svh`;
- исключить горизонтальный overflow.

---

# Reduced motion

Поддержи:

```css
@media (prefers-reduced-motion: reduce)
```

В этом режиме:

- не проигрывать полный бесконечный motion-цикл;
- показать статичную финальную композицию;
- оставить логотип, краткий оффер и CTA;
- не скрывать важный контент.

Статичный вариант:

```text
NYRAFLOW
Websites, automations, integrations and Telegram apps for business.
Start a project
```

---

# SEO и доступность

Анимация не должна состоять только из декоративных `div`.

Требования:

- на странице должен оставаться один логичный `h1`;
- основной смысл hero должен быть доступен поисковикам и screen reader;
- динамически меняющиеся слова не должны создавать бессмысленное многократное чтение;
- декоративные дубликаты можно пометить `aria-hidden="true"`;
- статичный доступный текст можно разместить визуально скрытым способом;
- CTA должен быть настоящей ссылкой или кнопкой;
- сохранить достаточный контраст.

Рекомендуемый смысл `h1`:

```text
Websites, automations, integrations and Telegram apps for business
```

Визуально `h1` можно интегрировать в финальную сцену или сделать доступным для screen reader без визуального дублирования.

# Производительность

- Не использовать приложенное видео на production-сайте.
- Не создавать сотни кадров.
- Не использовать тяжёлый canvas.
- Анимировать преимущественно `transform` и `opacity`.

- Не создавать одновременно все тяжёлые сцены поверх друг друга без необходимости.

- Не допускать layout shift.
- Не загружать hero позже основной разметки с заметным скачком.
- Сборка проекта должна завершаться без ошибок.

# Критерии готовности

Результат считается готовым, если:

- hero занимает весь первый экран;
- визуально и по ритму узнаваемо повторяет приложенный референс;
- текст адаптирован под Nyraflow;
- используются только Websites, Automations, Integrations и Telegram Apps;
- полный цикл автоматически повторяется бесконечно;
- между концом и началом нет резкого скачка;
- при нескольких циклах скорость не меняется;
- анимация не ломается в React StrictMode;
- CTA ведёт к `#contact`;
- header остаётся рабочим;
- desktop и mobile версии выглядят аккуратно;
- reduced-motion показывает полноценную статичную альтернативу;
- отсутствуют ошибки в консоли;
- production build проходит успешно;
- остальной сайт не изменён.
