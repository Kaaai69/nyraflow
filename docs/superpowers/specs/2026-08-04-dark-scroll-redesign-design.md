# Dark scroll redesign

## Цель

Обновить текущий лендинг MyLand в тёмной монохромной эстетике, заменить Spline-hero на управляемую прокруткой последовательность кадров и подготовить отдельный Vercel Preview. Публичные тексты, состав секций и порядок содержания остаются без изменений. Серверные интеграции на этом этапе не используются.

## Источники требований

- `DARK_THEME_SPEC.md` задаёт тёмную палитру и характер поверхностей.
- `HERO_SCROLL_ANIMATION.md` задаёт canvas-based image sequence, pinned hero и связь кадров с прокруткой.
- Текущий `content/home.ts` остаётся единственным источником публичного текста.
- Папка `upscayl_png_upscayl-standard-4x_2x/` содержит финальные исходники первой scroll-анимации: 90 последовательно пронумерованных PNG-кадров `1080×1080`.

Новые требования отменяют прежнее ограничение о неизменяемом Spline-hero и светлой теме.

## Визуальное направление

Это премиальный технологичный лендинг небольшой digital-команды для основателей и бизнес-заказчиков. Язык — тёмный, кинематографичный и сдержанный: почти чёрный фон, холодные серебряные частицы, ясная светлая типографика и один нейтральный акцент.

- `DESIGN_VARIANCE: 7` — асимметричная композиция без хаоса.
- `MOTION_INTENSITY: 7` — выразительный hero и спокойное движение ниже.
- `VISUAL_DENSITY: 3` — крупные поля, короткие смысловые группы, минимум декоративного шума.
- Основной фон: `#0B0C0E`.
- Основной текст: `#F1F5F9`.
- Вторичный текст: `#94A3B8`.
- Поверхности: `#16181D` с тонкой светлой границей; blur применяется только там, где он создаёт реальную глубину.
- Кнопки: светлая поверхность с тёмным контрастным текстом.

Существующие фотографии команды и проектов сохраняются. Их цветокоррекция выполняется только CSS-средствами и не меняет сами файлы.

## Структура страницы

Порядок существующих секций сохраняется. Меняются только композиция, стили, интервалы и motion-поведение:

1. Новый image-sequence hero.
2. Credibility и benefits.
3. Problem и metrics.
4. Work.
5. Services и pricing.
6. Team.
7. Process и starter.
8. FAQ.
9. Contact.
10. Footer.

Новые маркетинговые блоки, факты, цены, отзывы и CTA не добавляются. Текстовые значения из `content/home.ts` не редактируются.

## Hero и первая scroll-анимация

Hero занимает первый экран и закрепляется на время прокрутки. Canvas находится на тёмном фоне, а текст и навигация располагаются поверх него в отдельном смысловом слое.

Desktop-композиция:

- контент выровнен влево;
- сфера частиц находится по центру или немного правее;
- заголовок занимает не больше двух-трёх визуальных строк при сохранении исходного текста;
- CTA видны в первом viewport;
- длина scroll-сцены — ориентировочно `1800–2000px`, финальное значение определяется визуальной проверкой.

Mobile-композиция:

- анимация сохраняется;
- canvas масштабируется относительно ширины и высоты viewport без растягивания пропорций;
- текст остаётся читаемым поверх наиболее тёмной области кадра;
- длина закреплённой прокрутки уменьшается относительно desktop;
- device pixel ratio canvas ограничивается для стабильной частоты кадров и памяти.

Прогресс прокрутки преобразуется в индекс `0…89`. Отрисовка выполняется через `requestAnimationFrame`; повторная отрисовка того же кадра не производится. Первый кадр доступен до загрузки JavaScript. После завершения сцены hero плавно открепляется и передаёт прокрутку следующей секции.

Для `prefers-reduced-motion: reduce` используется доступный статичный ключевой кадр без закреплённой длинной сцены.

## Универсальный image-sequence компонент

Первая анимация реализуется через переиспользуемый компонент с явной конфигурацией:

- путь и шаблон имени кадров;
- количество кадров;
- длина scroll-сцены;
- правила масштабирования canvas;
- desktop/mobile параметры;
- fallback-кадр;
- режим reduced motion.

Компонент не содержит текст конкретной секции. Hero передаёт контент отдельным слоем. Такая граница позволит позднее подключить вторую scroll-анимацию без переписывания движка; до получения второго набора кадров новая пустая секция или placeholder не создаётся.

## Подготовка изображений

Исходные PNG весят около 27 МБ и не отдаются браузеру напрямую. Для сайта создаётся оптимизированная последовательность WebP в `public/animation/tunnel/` с той же нумерацией.

- Разрешение остаётся `1080×1080`.
- Конвертация не меняет порядок или число кадров.
- Качество подбирается по визуальному сравнению частиц и чёрного фона.
- Первый кадр загружается приоритетно.
- Остальные кадры предзагружаются управляемо, без одновременного декодирования всей последовательности на слабом мобильном устройстве.
- Ошибка отдельного кадра не ломает hero: остаётся последний успешно отрисованный кадр.

## Отказ от Spline

`ResponsiveHero`, `LockedSplineHero`, `MobileHero`, `SplineWheelBridge` и `lib/spline-navigation` удаляются из активного пути страницы. После подтверждения отсутствия других потребителей устаревшие компоненты, тесты и зависимость `@splinetool/react-spline` удаляются из проекта.

Новый hero не выполняет внешних запросов к Spline и не зависит от WebGL.

## Секции ниже hero

- Один тёмный фон проходит через всю страницу без резкого перехода после hero.
- Карточки используются только для реальной группировки; остальные блоки разделяются линиями, крупными полями и сменой композиции.
- Радиусы, рамки и интерактивные состояния образуют одну систему.
- Текущая Onest typography сохраняется, если визуальная проверка не выявит проблем с иерархией.
- Motion ниже hero строится на CSS и Intersection Observer; вторая тяжёлая animation-библиотека не добавляется.
- Все desktop grid-композиции имеют явный mobile fallback без горизонтального overflow.

## Форма и сервер

Contact-секция сохраняет поля, подписи и существующий текст, но preview-версия не вызывает `/api/contact` и не отправляет данные во внешние сервисы. Submit перехватывается локально без ложного сообщения об успешной отправке. API-route не удаляется, но остаётся неиспользуемым текущей страницей.

## Производительность и доступность

- Canvas не перехватывает pointer events.
- Текст и CTA остаются семантическим HTML, а canvas помечается декоративным.
- Контраст интерактивных элементов соответствует WCAG AA.
- Scroll остаётся нативным; запрещены глобальные wheel/touch-перехватчики.
- Canvas очищается и resize-обработчики снимаются при размонтировании.
- Максимальный объём web-ready последовательности контролируется после WebP-конвертации и проверяется на Vercel Preview.
- Навигация, клавиатурный фокус и legal pages сохраняют работоспособность.

## Проверка

- Unit-контракты для преобразования scroll progress в индекс кадра, генерации URL и выбора mobile/reduced-motion режима.
- Проверка всех 90 web-ready кадров: непрерывная нумерация, одинаковое разрешение, успешное декодирование.
- `npm test`, typecheck и production build после восстановления локальных зависимостей.
- Browser QA на `390×844`, `768×1024` и `1440×900`.
- Проверка начала, середины и конца scroll-сцены, плавного unpin и перехода к следующей секции.
- Проверка формы: при submit отсутствуют network-запросы.
- Проверка `prefers-reduced-motion`.
- Vercel Preview smoke test на отдельном URL.

- Ссылка preview передаётся для визуального согласования до любых действий с `main`.

## Зафиксированные ограничения

- Текст и содержание не меняются.
- Сервер и внешние формы не подключаются.
- Первая scroll-анимация работает на desktop и mobile.
- На сайте закладывается архитектура для двух scroll-анимаций, но реализуется только предоставленная первая.
- Вторая сцена добавляется после получения отдельного набора кадров и требований.
