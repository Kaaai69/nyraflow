# Холодная рассылка по нишам

Одно письмо-скелет + описание ниши = готовая рассылка. Текст письма правится
в одном месте, ниши добавляются одним блоком в `niches.json`, руками ничего
переписывать не нужно.

```
template.txt           первое письмо (общий каркас)
template-followup.txt  напоминание через 3 дня
niches.json            что подставляется под каждую нишу
render.mjs             сборка писем из выгрузки парсера
leads/                 сюда кладём выгрузки (в git не уходит)
out/                   готовые письма (в git не уходит)
```

## Как пользоваться

Посмотреть ниши и образец письма — до всякой рассылки:

```bash
node marketing/outreach/render.mjs --list
```

```bash
node marketing/outreach/render.mjs --niche detailing --preview
```

Собрать рассылку из выгрузки парсера:

```bash
node marketing/outreach/render.mjs --niche dental --leads marketing/outreach/leads/dental.csv
```

Через 3 дня — напоминание по той же базе (уходит ответом в ту же цепочку,
тема получает `Re:`):

```bash
node marketing/outreach/render.mjs --niche dental --leads marketing/outreach/leads/dental.csv --followup
```

На выходе в `out/<ниша>/`:

- `001-nazvanie.txt` … — по письму на лида, с готовой темой. Для ручной отправки.
- `mailing.csv` — колонки `email,subject,body,company,city,site`. Импортируется
  в любой сервис рассылки или в mail merge.

Флаги: `--limit 20` (взять первых 20), `--out <dir>` (своя папка),
`--help`.

## Что скрипт делает с грязной базой

Парсерные выгрузки всегда кривые, поэтому:

- Понимает CSV с `;`, `,` и табом, с кавычками и переносами внутри полей; JSON — тоже.
- Сам находит колонки: `email / e-mail / почта`, `название / компания / name`,
  `город`, `сайт`. Регистр и лишние слова в заголовке не мешают.
- Чистит название: `ООО "Дентал-Сити"` → `Дентал-Сити`.
- Если названия нет или оно мусорное (цифры, ссылка, длиннее 40 символов) —
  берёт тему **без названия**, а не `Сайт для ООО "" — ...`. Это главный
  способ выглядеть как спам, поэтому проверка жёсткая.
- Выкидывает битые адреса и дубли, в конце печатает, сколько чего отброшено.

## Добавить нишу

Блок в `niches.json` — четыре поля, которые реально меняются:

```json
"vet": {
  "title": "Ветклиники",
  "focus": "спасут ли здесь его животное",
  "subjects": ["Сайт для {{company}} — оплата, только если понравится"],
  "subjectsNoCompany": ["Сайт для ветклиники — оплата, только если понравится"]
}
```

Если в нише слово «заявка» звучит чужеродно — у кофейни это заказ или бронь —
добавляем два поля, они переопределяют общее значение:

```json
"actionTo": "заказа или брони",
"actionIn": "заказах"
```

`focus` — вопрос, который у клиента этой ниши в голове, когда он открыл сайт.
Подставляется в строку «Человек, который открыл ваш сайт, решает один вопрос:
…», поэтому пишется с маленькой буквы, без точки и одним вопросом, а не двумя.

Формулируем именно **вопрос клиента**, а не список того, что должно быть на
сайте. Перечисление функций («фото работ, прайс, онлайн-запись») в холодном
письме — угадывание чужого бизнеса вслепую: у половины базы этого либо нет и
не планируется, либо давно сделано, и письмо летит мимо. Вопрос в голове
посетителя есть всегда, промахнуться нечем.

И вопрос должен звучать нейтрально. «Не обманут ли его с ремонтом» — это уже
намёк, что получатель обманывает; «сделают ли нормально и за названные деньги»
описывает ту же тревогу, не задевая адресата.

Всё остальное письмо общее, и переписывать его под нишу не нужно — работает
оффер, а не количество подогнанных деталей.

Длину `focus` можно не считать: абзацы в шаблонах пишутся одной строкой,
а перенос по ширине письма делает сам скрипт (последний абзац — подпись —
он не трогает).

## Почему письмо не давит на «у вас нет сайта»

Рамка «у вас нет фото / нет цен / нет записи» ломается на первой же базе:
сайт есть у большинства, и получатель читает такое письмо как «мне пишут про
то, что у меня уже сделано». Дальше — удаление.

Поэтому разговор идёт не про наличие, а про конверсию: сайт есть у всех,
разница в том, сколько людей на нём доходит до заявки. Это верно и для тех,
у кого сайта нет, и для тех, у кого он хороший, — письмо не надо разводить
на два варианта.

Отдельная строка «если сайт уже есть — соберём второй вариант, сравните»
закрывает главное возражение прямо в письме и ничего не стоит: предложение
и так «сначала показываем, потом деньги».

Чего в письме сознательно нет — обещанных процентов конверсии и цифр роста.
В холодном письме незнакомцу они читаются как враньё и стоят дороже, чем дают.

## Правила отправки

- 20–30 писем в день с одного ящика, не больше. Резкий рост — прямой путь в спам.
- Обычный текст: без HTML-подписи, картинок и трекинговых пикселей.
- Ссылка одна и только в подписи. Отдельная строка «мои работы: …» из письма
  убрана намеренно: она читается как просьба посмотреть портфолио и роняет
  позицию ещё до ответа.
- Темы в `subjects` чередуются автоматически: одинаковая тема на всю базу
  собирается фильтрами в один отпечаток.
- Ответы приходят на обычный ящик — отвечаем руками, это не автоматизируется.
