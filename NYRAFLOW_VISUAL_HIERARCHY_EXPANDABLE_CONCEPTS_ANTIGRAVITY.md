# NYRAFLOW — VISUAL HIERARCHY & EXPANDABLE CONCEPTS
## React / Antigravity implementation prompt

## Контекст

Нужно улучшить текущую визуальную версию сайта Nyraflow:

`https://myland-sooty.vercel.app/`

Проект уже собран на React и редактируется в Antigravity.

После перехода на полностью чёрно-белую палитру сайт стал визуально чище, но потерял структурный контраст:

- смысловые группы текста недостаточно отделены друг от друга;
- блоки с разными функциями выглядят слишком одинаково;
- после удаления прежних карточек исчезла читаемая группировка информации;
- многие секции воспринимаются как один длинный монотонный текстовый поток;
- белые секции почти не отличаются друг от друга;
- чёрные секции также выглядят одинаково;
- блок концептов выводит слишком много контента одновременно;
- каталог концептов должен быть компактным в исходном состоянии и раскрываться по взаимодействию.

Цель — сохранить строгую чёрно-белую эстетику, но добавить:

- визуальную иерархию;
- структурный ритм;
- понятные границы смысловых групп;
- редакционную композицию;
- контролируемые карточки и панели;
- интерактивный раскрывающийся каталог концептов.

Это не новый редизайн с нуля.  
Не менять тексты, услуги, цены, бизнес-логику, ссылки и порядок основных разделов.

# КРИТИЧЕСКИ ВАЖНО: ДВЕ АНИМАЦИИ НЕ ТРОГАТЬ

На сайте существуют две разные анимации.

## 1. Полноэкранная hero-анимация

Не менять:

- сцены;
- тексты;
- тайминги;
- цвета внутри утверждённой монохромной системы;
- переходы;
- state machine;
- бесконечный цикл;
- React-логику;
- mobile-поведение;
- CTA;
- header synchronization.

## 2. Анимация «Мы создаём» перед ценами

Не менять:

- текст `Мы создаём`;
- английские направления;
- порядок направлений;
- тайминги;
- смену текста;
- цикл;
- механику;
- расположение перед блоком цен.

Обе анимации должны остаться отдельными независимыми компонентами.

Разрешено только убедиться, что внешние соседние секции используют те же фоновые токены и не создают цветового шва.

# СТРУКТУРНЫЙ КОНТРАСТ

## Не отказываться от карточек полностью

Предыдущая версия слишком радикально убрала карточки.  
Карточки допустимы и нужны там, где они помогают считывать отдельные предложения или группы данных.

Но карточки должны быть редакционными, а не SaaS-плитками.

## Новая система карточек

### Light card

```css
background: var(--paper-elevated);
border: 1px solid var(--line-on-light);
border-radius: 10px;
box-shadow: none;
```

### Dark card

```css
background: var(--dark-surface-elevated);
border: 1px solid var(--line-on-dark);
border-radius: 10px;
box-shadow: none;
```

### Hover

```css
transform: translateY(-2px);
border-color: var(--line-strong-light or dark);
transition: 220ms cubic-bezier(0.22, 1, 0.36, 1);
```

Не использовать:

- большие мягкие тени;
- glassmorphism;
- сильный blur;
- radius 24–40px;
- разноцветные иконки;
- декоративные градиенты.

# 1. БЛОК С ТРЕМЯ ПРИНЦИПАМИ

Тексты:

- Прямой контакт с командой;
- Один процесс от идеи до запуска;
- Основа для развития.

## Проблема

Сейчас элементы недостаточно отделены и воспринимаются как один поток.

## Новое оформление

На desktop:

- три колонки;
- общий верхний и нижний border;
- вертикальные разделители между колонками;
- номер `01`, `02`, `03`;
- небольшая служебная подпись;
- крупный заголовок;
- отдельный абзац;
- внутренние отступы 32–48px.

Не нужно помещать каждую колонку в отдельную округлую карточку.

Пример:

```text
01
Прямой контакт с командой
Описание

│

02
Один процесс от идеи до запуска
Описание

│

03
Основа для развития
Описание
```

На mobile:

- вертикальный список;
- каждая строка отделена горизонтальной линией;
- номера остаются видимыми.


Только если это улучшает композицию и не выглядит случайным.

# 4. КОНЦЕПТЫ — РАСКРЫВАЮЩИЙСЯ КАТАЛОГ

## Главная задача

Концепты не должны быть полностью видны сразу.

В исходном состоянии пользователь должен видеть компактный список проектов.  
Изображение, расширенное описание и CTA появляются только после раскрытия выбранного концепта.

Не использовать обычную сетку из десяти полностью раскрытых карточек.

---

## Desktop-композиция

Сделать вертикальный accordion / expandable project index.

Каждый проект в закрытом состоянии занимает приблизительно:

```text
84–108px
```

В закрытой строке показывать:

- номер проекта: `01`, `02`, `03`...;
- название;
- категорию;
- статус или короткий label при наличии;
- справа текст `Открыть`;
- минимальную стрелку / `+`;
- верхнюю или нижнюю разделительную линию.

Пример:

```text
01     Atelier Kitchens          Кухонная студия          Открыть  +
02     Лингва.Академия           Онлайн-школа языков      Открыть  +
03     Silenzio                  Загородный глэмпинг      Открыть  +
```

Все проекты должны быть закрыты при первом отображении секции.

Не раскрывать первый проект автоматически.

---

## Раскрытое состояние концепта

После клика строка расширяется.

Внутри показать:

### Левая или верхняя часть

- крупный preview существующего проекта;
- использовать уже имеющееся изображение;
- не создавать новое изображение;
- сохранить корректный aspect ratio;
- media container с `overflow: hidden`;
- grayscale treatment допустим только если он не уничтожает смысл дизайна проекта.

### Правая или нижняя часть

- номер;
- название;
- категория;
- существующее описание, если оно уже есть в данных;
- краткий контекст;
- CTA `Открыть проект`;
- внешний URL проекта;
- стрелка внешней ссылки.

Ориентировочная раскрытая высота desktop:

```text
480–680px
```

Высота должна зависеть от контента, а не быть жёстко зафиксирована.

---

## Поведение accordion

- одновременно раскрыт максимум один концепт;
- открытие нового закрывает предыдущий;
- повторный клик по открытому концепту закрывает его;
- анимация высоты плавная;
- использовать opacity и translateY для внутреннего контента;
- не использовать bounce;
- не использовать резкий `display: none`;
- сохранять scroll position;
- не прокручивать страницу автоматически без необходимости;
- не открывать внешний проект при клике по всей строке;
- внешний проект открывается только через отдельную CTA.

---

## Mobile

На mobile:

- каждая строка вертикальная;
- название и категория не должны сталкиваться;
- preview появляется под заголовком;
- CTA находится внутри раскрытой панели;
- не полагаться на hover;
- весь header строки — настоящая button;
- touch target минимум 44px;
- исключить горизонтальный overflow.

---

## Доступность accordion

Каждая строка:

- `<button>`;
- `aria-expanded`;
- `aria-controls`;
- уникальный `id`;
- доступна с клавиатуры;
- Enter / Space раскрывают;
- focus-visible заметен;
- иконка меняется `+` → `−`;
- screen reader получает название концепта и состояние.

Не вкладывать интерактивную ссылку внутрь кнопки accordion header.  
CTA проекта размещать только внутри раскрытой панели.

# ТЕХНИЧЕСКАЯ РЕАЛИЗАЦИЯ В REACT

## Для концептов

Создать отдельный компонент, например:

```text
ExpandableProjects
ProjectAccordionItem
```

State:

```js
const [openProjectId, setOpenProjectId] = useState(null);
```

Логика:

- `null` — все закрыты;
- click closed item → open its id;
- click open item → null;
- click another item → new id.

Если в проекте уже есть Framer Motion, использовать его.  
Если нет, не добавлять тяжёлую библиотеку только ради accordion.

Можно использовать:

- CSS grid row transition;
- measured height;
- существующий animation utility.

Не использовать нестабильный hardcoded `max-height: 2000px`, если можно реализовать аккуратнее.

# КРИТЕРИИ ГОТОВНОСТИ

Работа считается готовой, если:

- сайт остаётся полностью чёрно-белым;
- синий цвет не возвращён;
- контент больше не выглядит единым монотонным потоком;
- смысловые группы легко считываются;
- карточки используются только там, где помогают структуре;
- карточки не выглядят как типовой SaaS UI-kit;
- принципы разделены линиями и номерами;
- problem-блоки снова визуально сгруппированы;
- статистика оформлена отдельной полосой;
- концепты в исходном состоянии компактны;
- ни один концепт не раскрыт автоматически;
- одновременно открыт максимум один концепт;
- preview и CTA видны только в раскрытом состоянии;
- все десять проектов и ссылки сохранены;
- accordion работает на клавиатуре;
- mobile accordion не ломается;
- `Быстрый старт` снова имеет чёткие карточки;
- тарифы визуально разделены;
- две существующие анимации не изменены;
- между анимациями и сайтом нет цветового шва;
- нет horizontal overflow;
- нет ошибок в console;
- production build проходит успешно.
