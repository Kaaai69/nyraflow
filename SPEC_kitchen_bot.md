# Спецификация: демо-бот для мебельщиков (кухни на заказ)

## 1. Контекст

Автор — Фёдор, разработчик (студия nyraflow). Пишет продавцам кухонь на заказ на Авито. Гипотеза, подтверждённая в переписке: у мебельщиков много времени уходит на расчёты людям, которые потом пропадают. Клиенты спрашивают «сколько стоит кухня», рассылают размеры в 5–10 компаний, получают «от 150 000» и исчезают.

Один владелец мебельной компании (сам пробовал собирать бота) назвал главные проблемы обычных чат-ботов:
- работают только по жёсткому алгоритму, шаг в сторону — ломаются;
- забывают переписку;
- задают однотипные вопросы, переспрашивают уже сказанное.

**Цель демо:** живая ссылка на Telegram-бота, которую можно отправить мебельщику со словами «попробуйте как клиент, попробуйте сломать». Бот должен выдержать такую проверку.

**Дальнейшая цель:** та же логика подключается к чатам Авито через официальный API (вебхук мессенджера). Поэтому ядро логики должно быть отделено от Telegram.

## 2. Что делает бот (сценарий клиента)

1. Клиент пишет в свободной форме, например: «сколько стоит угловая кухня метра 3?».
2. Бот уточняет недостающие данные — **по одному короткому вопросу за раз**, обычным человеческим языком, без анкеты и без кнопок-опросника.
3. Как только данных достаточно для расчёта — присылает **ориентировочную вилку цены** и оговорку, что точная цена считается после бесплатного замера.
4. Предлагает бесплатный замер, просит имя, телефон и удобное время.
5. Получив телефон — благодарит, говорит, что менеджер свяжется, и отправляет менеджеру выжимку.

## 3. Собираемые данные (поля)

| Поле | Обязательно для цены | Описание |
|---|---|---|
| `length_m` | да | Суммарная длина по всем стенам, м (для угловой «2,4 и 1,8» = 4,2) |
| `facade` | да | Материал фасадов, одно из значений прайса |
| `shape` | нет (по умолчанию прямая) | прямая / угловая / П-образная |
| `island` | нет | есть ли остров (bool) |
| `countertop` | нет (по умолчанию ЛДСП) | материал столешницы, из прайса |
| `upper_to_ceiling` | нет | верхние шкафы до потолка (bool) |
| `budget` | нет | бюджет клиента, текст |
| `timeline` | нет | когда нужна кухня |
| `location` | нет | город / район |
| `notes` | нет | пожелания: техника, цвет, стиль — накапливаются |
| `name` | нет | имя |
| `phone` | нет | телефон — триггер передачи менеджеру |
| `measure_time` | нет | удобное время замера |

## 4. Ключевые принципы

1. **Цену считает код, не нейросеть.** Нейросеть только извлекает данные из текста и ведёт разговор. Вилку считает детерминированная формула по прайсу. Нейросети запрещено называть любые цифры цены самой.
2. **Память диалога:** в каждый вызов нейросети передаётся текущее состояние полей + последние ~20 сообщений. Бот никогда не переспрашивает известное.
3. **Свободный текст:** одно сообщение может содержать сразу несколько полей («угловая 2,4 и 1,8, эмаль, до 400») — всё извлекается за раз.
4. **Пересчёт:** если клиент меняет параметр после выдачи вилки («а если пластик?») — бот присылает новую вилку.
5. **Вопросы не по сценарию** (сроки изготовления, гарантия, рассрочка, фурнитура): бот отвечает по справке о компании из конфига и возвращается к сбору данных. Если ответа в справке нет — говорит «уточню у менеджера» и пересылает вопрос менеджеру. Никаких выдуманных фактов.
6. **Тон:** вежливый живой менеджер, коротко, без канцелярита, без эмодзи-спама.

## 5. Прайс и справка (конфиг)

Отдельный файл `config.json` — единственное, что меняется под конкретного мебельщика. Код не трогается.

```json
{
  "company": {
    "name": "Кухни на заказ (демо)",
    "info": "Бесплатный замер по Москве и области. Срок изготовления 25–35 рабочих дней. Гарантия 2 года. Фурнитура Blum / Boyard. Рассрочка без переплат на 6 месяцев."
  },
  "manager_chat_id": null,
  "demo_mode": true,
  "pricing": {
    "facades": {
      "ЛДСП": [18000, 24000],
      "МДФ плёнка": [24000, 32000],
      "МДФ пластик": [30000, 40000],
      "МДФ эмаль": [35000, 48000],
      "акрил": [38000, 50000],
      "шпон/массив": [55000, 80000]
    },
    "countertops": {
      "ЛДСП": [0, 0],
      "компакт-плита": [8000, 12000],
      "искусственный камень": [25000, 40000],
      "кварц": [35000, 55000]
    },
    "shapes": { "прямая": 1.0, "угловая": 1.08, "П-образная": 1.15 },
    "island": [60000, 120000],
    "upper_to_ceiling": 1.15,
    "round_to": 5000
  }
}
```

Цифры — демонстрационные средние, должны быть явно помечены как демо.

**Формула** (отдельно для нижней и верхней границы):

```
за_метр = фасад + столешница
итог = length_m × за_метр × коэф_формы × (коэф_до_потолка, если да) + (остров, если да)
округлить до round_to
```

Вывод клиенту: «Ориентировочно 380–460 тыс. ₽. Точную стоимость посчитаем после бесплатного замера — по реальным размерам и выбранным материалам».

## 6. Контракт с нейросетью

Каждое сообщение клиента → один вызов нейросети. Нейросеть возвращает строго JSON:

```json
{
  "reply": "текст ответа клиенту",
  "updates": { "facade": "МДФ эмаль", "length_m": 4.2 },
  "needs_manager": false,
  "manager_question": null
}
```

- `updates` — только новые/изменённые поля. Значения `facade`, `countertop`, `shape` нейросеть обязана привести к одному из ключей прайса; код отбрасывает значения не из списка.
- `notes` в `updates` дописывается к существующим, а не заменяет.
- `needs_manager: true` + `manager_question` — когда клиент спросил то, чего нет в справке.
- В системный промпт передаются: справка о компании, списки допустимых значений из прайса, текущее состояние полей, правила (по одному вопросу, не называть цены самой, когда цена готова — бот пришлёт её сам).
- Запросы с `response_format: json_object`, `temperature` ~0.3. Если JSON не распарсился — повторить запрос один раз, иначе вежливо переспросить клиента.

## 7. Передача менеджеру

Триггер: появился `phone` (один раз на диалог), а также `needs_manager`.

Формат:

```
🔔 Новая заявка
Иван (@username), +7 999 …
Кухня: угловая, 4,2 м, МДФ эмаль, столешница кварц, верх до потолка, без острова
Бюджет: до 450 тыс. · Сроки: январь · Район: Химки
Замер: суббота после 12
Ориентир: 380–460 тыс. ₽
Пожелания: встроенный холодильник, светлые фасады
```

**Демо-режим** (`demo_mode: true`): выжимка дополнительно отправляется самому тестирующему с подписью «👀 Так это увидит менеджер». Мебельщик видит обе стороны сразу.

## 8. Архитектура

- **Python**, асинхронно.
- **Ядро** (`core.py`): состояние сессии, вызов нейросети, слияние полей, расчёт цены, формирование выжимки. Функция вида `process_message(session, text, user_label) -> list[OutgoingMessage]` — без зависимости от Telegram.
- **Транспорт** (`telegram_bot.py`): python-telegram-bot или aiogram. Команды `/start` (приветствие + первый вопрос), `/reset` (начать заново). Позже рядом появится `avito_webhook.py` с тем же ядром.
- **Нейросеть** — через OpenAI-совместимый API, настраивается переменными окружения: `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`. По умолчанию DeepSeek (дёшево, работает из РФ, хороший русский). Можно подставить GigaChat, YandexGPT и др.
- **Секреты** только в `.env`: `TELEGRAM_TOKEN`, `LLM_*`.
- **Хранение сессий** — для демо в памяти (или JSON-файл, чтобы переживать перезапуск).
- **Запуск** — на VPS (бот должен работать постоянно). Из-за ограничений Telegram в РФ сервер предпочтительно зарубежный.

## 9. Сценарии проверки («попробуй сломать»)

Демо готово, только если все проходят:

1. Всё одним сообщением: «угловая 2,4 и 1,8, эмаль, кварц, до 450, в январе» → сразу вилка, без лишних вопросов.
2. По шагу, короткими ответами («3 метра», «мдф») → бот не теряет контекст.
3. Смена параметра после цены: «а если пластик?» → новая вилка.
4. Вопрос не по теме в середине: «а гарантия какая?» → ответ из справки и возврат к сбору.
5. Вопрос, которого нет в справке: «вы делаете гардеробные?» → «уточню у менеджера», вопрос ушёл менеджеру.
6. Клиент отвечает на другой вопрос, не на заданный → бот принимает данные и не переспрашивает.
7. Клиент сам называет цифру: «соседи предлагают за 200, сделаете?» → бот не обещает цену, отвечает по вилке и зовёт на замер.
8. Опечатки, сленг, «ну метра три где-то» → данные извлекаются.
9. Клиент уходит от ответа про телефон → бот не давит, предлагает замер ещё раз позже, один раз.
10. Повторный `/start` и `/reset` → чистый диалог.
11. Длинный разговор 30+ сообщений → бот не забывает, что было в начале.
12. Отказ отвечать на вопросы («просто скажите цену») → бот даёт вилку по известному с оговоркой и предлагает уточнить для точности.

## 10. План работ

1. Конфиг: прайс и справка о компании (демо).
2. Ядро: состояние, вызов нейросети, слияние, расчёт, выжимка.
3. Telegram-обвязка, `/start`, `/reset`, демо-режим.
4. Прогон сценариев из раздела 9, правка промпта.
5. Деплой на VPS, ссылка на бота для рассылки.

## 12. Ограничения, о которых честно говорить мебельщикам

- Вилка — ориентир, а не смета. Точная цена после замера.
- Демо работает в Telegram. На Авито подключается через официальный API к аккаунту мебельщика — для доступа к чатам нужен его тариф Авито («Pro» / «Максимальный», уточнять у конкретного клиента).
- Бот только отвечает тем, кто написал сам, никому не пишет первым.
